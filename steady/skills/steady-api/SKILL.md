# Steady API

You call the API directly with curl. The runtime injects your token as
`STEADY_TOKEN`; every request is:

```bash
curl -s https://service.steady.space/api/v2/<path> \
  -H "Authorization: Bearer $STEADY_TOKEN"
```

This sheet is your complete reference — never fetch the OpenAPI spec or
docs pages during a run. On `429`, sleep the `Retry-After` seconds and
retry once.

## Conventions

- IDs are UUIDs. `date` fields are `YYYY-MM-DD`; `*_at` fields ISO 8601.
- Array params use the `name[]=` form. Lists paginate with `page` and
  `per_page`, newest first, and filter with `since`/`until` (inclusive).
- Long-form fields (`previous`, `intentions`, `blockers`, `body`) are
  Markdown; `@username` mentions link and notify.
- Writes send JSON: add `-H "Content-Type: application/json"`.

## Endpoints

**Identity** — `GET /me` → the authenticated person: `id`, `teams[]`.

**Action items** — `GET /action-items` → open items, each with an edit
link to the record it's asking about.

**Check-ins** — pre-generated by Steady; there is no POST.

- `GET /check-ins?since=&until=&people_ids[]=&team_ids[]=&blocked=`
- `PATCH /check-ins/{date}` (or `{uuid}`) with any of `previous`,
  `intentions`, `blockers`, `previous_completed`, `mood`, `team_ids[]`.
  A 404 means no check-in exists that day (off-schedule or absent) —
  that's an answer, not an error to work around.

**Comments and reactions** — on check-ins and goal updates:

- `GET|POST /check-ins/{id}/comments` · `GET /check-ins/{id}/reactions`
- `GET|POST /goal-updates/{id}/comments` · `GET /goal-updates/{id}/reactions`
- POST body: `{ "body": "markdown" }`

**Digest** — `GET /digest?category=comment&per_page=` → recent digest
entries, newest first.

**Goals** — full CRUD:

- `GET /goals?people_ids[]=&team_ids[]=` · `GET /goals/{id}`
- `POST /goals` and `PATCH /goals/{id}` with `title`, `description`,
  `start_date`, `end_date`, `owner_id`, `team_ids[]`,
  `contributor_ids[]`, `update_cadence`, `parent_id`, `private`,
  `archived`

**Goal updates** — nested create, flat access:

- `GET|POST /goals/{goal_id}/goal-updates`, then
  `GET|PATCH|DELETE /goal-updates/{id}`
- Fields: `title`, `body`, `progress` (0–100), `confidence` (snaps to
  30/60/90 = off track / at risk / on track). Omitted `progress` and
  `confidence` carry forward from the previous update.
